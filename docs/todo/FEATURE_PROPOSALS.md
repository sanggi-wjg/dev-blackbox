# Feature Proposals

기능 확장 제안서. 현재 시스템 분석, 시장 조사, 경쟁 제품 비교를 기반으로 작성.

> 현재 아키텍처는 [ARCHITECTURE.md](../ARCHITECTURE.md) 참고.

## 현재 상태 요약

| 영역     | 현재 기능                               |
|--------|-------------------------------------|
| 데이터 수집 | GitHub (커밋), Jira (이슈), Slack (메시지) |
| AI 기능  | Ollama 기반 플랫폼별 업무 일지 요약             |
| 분석     | 기여도 히트맵 (GitHub 스타일), 스트릭 계산        |
| 태스크    | Jira 백로그 동기화, CRUD, 정렬              |
| 인프라    | 분산 락, 멱등성, 캐싱, 벡터 임베딩 (미사용)         |

## 시장 포지셔닝

오픈소스 생태계에서 **GitHub + Jira + Slack 수집 → LLM 요약 → 통합 업무 일지**를 모두 갖춘 프로젝트는 없다.
상용 제품 중 Pensero의 "What Happened Yesterday"가 가장 유사하지만, Dev-Blackbox는 **셀프호스팅 + 로컬 LLM**이라는 차별점을 가진다.

| 제품               | 특징                            | 참고 포인트                    |
|------------------|-------------------------------|---------------------------|
| Pensero          | AI 네이티브, 프라이버시 우선, 일일 활동 가시성  | "What Happened Yesterday" |
| Jellyfish        | 리소스 배분, 스프린트 성과, 투자 분배 분석     | 팀/프로젝트 대시보드               |
| Faros AI         | 100+ 데이터 소스, 자연어 쿼리, 온프레미스 배포 | 자연어 인터페이스, DORA 메트릭스      |
| LinearB          | AI PR 리뷰, 실시간 대시보드, 워크플로우 자동화 | PR 사이클 타임 분석              |
| Pluralsight Flow | 언어별 생산성, 코드 이탈률, 페어 프로그래밍 지원  | 투자 분배 분석                  |

| Geekbot          | 20만+ 사용자, 비동기 스탠드업, AI 감성 분석  | Slack 리포트 자동 발송           |
| Swarmia          | 개발자 퍼스트, 비즈니스 아웃컴 중심          | 팀 자율성 + 투명성               |

## 기능 제안

### Phase 1 — 기존 인프라 활용 (빠른 성과)

#### 1. 벡터 임베딩 활성화 + 시맨틱 검색

**현재**: `PlatformWorkLog.embedding`, `DailyWorkLog.embedding` 컬럼(1024차원)과 pgvector가 이미 존재하지만 미사용.

**제안**:

- 업무 일지 저장 시 LLM 임베딩 모델로 벡터 생성 후 저장
- "지난주 인증 관련 작업" 같은 자연어 검색 API 추가
- 유사 업무 일지 추천 (과거 비슷한 작업 이력 조회)

**기대 효과**: 업무 일지 시스템의 핵심 가치인 "과거 기록 검색"을 자연어로 가능하게 함.

**구현 범위**:

- 임베딩 생성 로직 추가 (LlamaIndex embedding model)
- 시맨틱 검색 API 엔드포인트
- 기존 데이터 마이그레이션 (배치 임베딩 생성)

---

#### 2. 주간/월간 요약 리포트

**현재**: 일일 업무 일지만 존재. 주간/월간 집계 없음.

**제안**:

- 일일 업무 일지를 LLM으로 재요약하여 주간/월간 리포트 생성
- 주요 성과, 진행 중인 작업, 블로커 자동 분류
- 스케줄러 태스크로 매주 월요일 / 매월 1일 자동 생성

**기대 효과**: 경영진/팀 리드에게 즉시 공유 가능한 요약 리포트. Pensero, Jellyfish 등 모든 경쟁 제품의 핵심 기능.

**구현 범위**:

- `WeeklyWorkLog`, `MonthlyWorkLog` Entity
- 주간/월간 요약 프롬프트 템플릿
- 스케줄러 태스크 추가
- 조회 API 엔드포인트

---

#### 3. Slack 자동 리포트 발송

**현재**: Slack에서 데이터를 수집만 하고, 결과를 Slack으로 보내지 않음.

**제안**:

- 생성된 일일/주간 요약을 지정된 Slack 채널로 자동 전송
- 사용자별 DM 전송 옵션
- SlackClient에 메시지 전송 기능 추가

**기대 효과**: Geekbot(20만+ 사용자)의 핵심 가치. 별도 대시보드 접속 없이 Slack에서 바로 업무 일지 확인.

**구현 범위**:

- SlackClient 메시지 전송 메서드
- 발송 대상 채널/사용자 설정
- 스케줄러 태스크 연동

---

### Phase 2 — 경쟁력 확보

#### 4. 프롬프트/모델 커스터마이징 API

**현재**: 프롬프트와 LLM 설정이 코드에 하드코딩. `llm_agent.py`에 TODO로 계획됨.

**제안**:

- 프롬프트 템플릿을 DB에 저장하고 CRUD API 제공
- LLM 모델/파라미터를 API로 변경 가능하게
- 팀별/사용자별 맞춤 프롬프트 지원

**기대 효과**: 팀마다 다른 요약 스타일, 언어, 상세 수준 적용 가능.

**구현 범위**:

- `PromptTemplate` Entity
- 프롬프트 관리 API (Admin)
- LLM Agent에서 DB 프롬프트 로드

---

#### 5. PR 사이클 타임 분석

**현재**: GitHub에서 PushEvent만 수집. PullRequestEvent, PullRequestReviewEvent는 미수집.

**제안**:

- PullRequestEvent, PullRequestReviewEvent 수집 추가
- PR 생성 → 첫 리뷰 → 승인 → 머지까지 각 단계별 소요 시간 측정
- PR 크기(변경 라인 수)와 리뷰 시간 상관관계 분석

**기대 효과**: LinearB, GitClear의 핵심 기능. 코드 리뷰 병목 조기 발견.

**구현 범위**:

- GitHub 이벤트 수집 확장 (PR 관련 이벤트)
- `PullRequestCycleTime` 분석 로직
- 분석 결과 조회 API

---

#### 6. DORA 메트릭스 (기본)

**현재**: DORA 지표 없음.

**제안**:

- **Lead Time for Changes**: PR 생성 → 머지 시간 (PR 데이터 필요, #5 의존)
- **Deployment Frequency**: 배포 빈도 (CI/CD 웹훅 또는 GitHub Actions 연동)
- **Change Failure Rate**: 배포 후 롤백/핫픽스 비율
- **MTTR**: 장애 감지 → 복구 시간

**기대 효과**: 업계 표준 지표. 2025 DORA 리포트 이후 거의 모든 엔지니어링 플랫폼의 기본 기능.

**구현 범위**:

- DORA 메트릭 계산 로직 (domain 레이어)
- 메트릭 저장 Entity
- 대시보드 조회 API
- 업계 벤치마크 비교 기능

---

### Phase 3 — 팀 스케일

#### 7. 팀/프로젝트 대시보드

**현재**: 개인 단위만 지원. 팀 개념 없음.

**제안**:

- `Team` Entity 추가 (User N:M 관계)
- 팀 단위 기여도 집계, 업무 일지 통합 조회
- 프로젝트별 활동 분류 및 비교

**기대 효과**: 개인 도구에서 팀 도구로 확장. Jellyfish, Swarmia의 핵심 가치.

**구현 범위**:

- `Team`, `TeamMember` Entity
- 팀 관리 Admin API
- 팀 대시보드 조회 API

---

#### 8. GitLab/Bitbucket 연동

**현재**: GitHub만 지원. `Platform` Enum에 Confluence가 정의되어 있지만 미구현.

**제안**:

- GitLab API 연동 (이벤트, MR, 커밋)
- Bitbucket API 연동 (이벤트, PR, 커밋)
- Confluence 페이지 수집 + 요약 (Enum 이미 존재)

**기대 효과**: GitHub 외 플랫폼 사용 팀으로 사용 범위 확대.

**구현 범위**:

- `GitLabClient`, `BitbucketClient` 추가
- 플랫폼별 이벤트 수집 + 요약 파이프라인
- Secret 관리 API 확장

---

#### 9. 자연어 쿼리 인터페이스

**현재**: 정형화된 API만 존재.

**제안**:

- "이번 달 가장 많이 기여한 프로젝트는?" 같은 자연어 질문 처리
- LLM이 질문을 분석 → 적절한 데이터 조회 → 답변 생성
- 시맨틱 검색(#1)과 결합하여 컨텍스트 기반 답변

**기대 효과**: Faros AI가 이 기능으로 차별화. 비개발자(PM, 리더)도 데이터 접근 가능.

**구현 범위**:

- 질문 분석 → 쿼리 변환 LLM 파이프라인
- 벡터 검색 + 구조화 쿼리 하이브리드
- 대화형 API 엔드포인트

---

### Phase 4 — 장기 비전

#### 10. 개발자 웰빙 지표

**현재**: 활동량만 추적. 업무 패턴 분석 없음.

**제안**:

- 야근/주말 작업 빈도 감지
- 메시지 응답 시간 패턴 분석
- 연속 고강도 작업 기간 경고 (번아웃 조기 감지)
- SPACE 프레임워크 "Satisfaction" 차원 구현

**기대 효과**: Geekbot AI 감성 분석, Swarmia 팀 건강 지표의 셀프호스팅 대안.

---

#### 11. 투자 분배 분석

**현재**: 활동 데이터를 카테고리별로 분류하지 않음.

**제안**:

- 커밋/이슈를 "신기능 vs 유지보수 vs 기술부채 vs 버그픽스"로 LLM 자동 분류
- 기간별 투자 비율 트렌드 시각화
- "엔지니어링 시간이 어디에 쓰이는가" — 리더들의 1순위 질문에 답변

**기대 효과**: Jellyfish, Pluralsight Flow의 핵심 기능.

---

#### 12. AI 코딩 도구 임팩트 측정

**현재**: AI 도구 사용 추적 없음.

**제안**:

- Copilot/Claude Code 도입 전후 생산성 지표 비교
- AI 생성 코드 비율 추적 (커밋 메타데이터 분석)
- 코드 품질 지표와 AI 사용률 상관관계

**기대 효과**: 2025 DORA 리포트 이후 급부상 중인 영역. Faros AI, GitClear가 진입 중. 기존 수집 데이터로 분석 가능.

---

#### 13. 온콜/인시던트 연동

**현재**: 인시던트 관리 미지원.

**제안**:

- PagerDuty/Opsgenie API 연동
- 인시던트 대응 기록 자동 수집 및 요약
- MTTR (Mean Time to Restore) 자동 측정

**기대 효과**: DORA 메트릭스(#6) 완성을 위한 필수 데이터 소스.
