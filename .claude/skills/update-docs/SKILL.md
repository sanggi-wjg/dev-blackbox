# update-docs

코드 변경사항을 분석하여 관련 문서를 업데이트하는 스킬.
새로운 기능 추가, 구조 변경, 컨벤션 변경 등이 문서에 정확히 반영되도록 한다.

## 입력

사용자에게 다음 정보를 확인한다:

1. **변경 범위** — 어떤 코드가 변경되었는가 (파일명, 기능 설명, 또는 "최근 커밋 기준")
2. **업데이트 대상** — 특정 문서 지정 또는 자동 판별 (기본: 자동 판별)

## 변경 분석

### 1단계: 변경사항 파악

사용자가 "최근 커밋 기준"으로 요청하면 `git diff`로 변경사항을 파악한다.
그 외에는 사용자가 명시한 변경 범위를 기준으로 한다.

```bash
# 최근 커밋 기준
git diff HEAD~1 --name-only
git diff HEAD~1 --stat

# main 브랜치 기준
git diff main --name-only
git diff main --stat
```

### 2단계: 영향 받는 문서 판별

변경된 파일의 레이어/도메인에 따라 업데이트가 필요한 문서를 판별한다:

| 변경 영역                                  | 영향 받는 문서                                               |
|----------------------------------------|--------------------------------------------------------|
| `storage/rds/entity/`                  | `DATABASE.md`, `ERD.md`                                |
| `storage/rds/repository/`              | `DATABASE.md`                                          |
| `controller/api/`, `controller/admin/` | `API.md`                                               |
| `controller/config/`                   | `API.md` (예외 처리), `CONVENTIONS.md` (인증)                |
| `service/`                             | `CONVENTIONS.md` (패턴 변경 시), `PIPELINE.md` (파이프라인 관련 시) |
| `task/`                                | `PIPELINE.md`                                          |
| `client/`                              | `CONVENTIONS.md` (클라이언트 패턴), `PIPELINE.md` (수집 흐름)     |
| `agent/`                               | `PIPELINE.md` (LLM 관련)                                 |
| `core/`                                | `INFRASTRUCTURE.md`, `CONVENTIONS.md`                  |
| `docker/`                              | `INFRASTRUCTURE.md`, `DATABASE.md` (init.sql 변경 시)     |
| `main.py`, 프로젝트 설정                     | `ARCHITECTURE.md`                                      |
| 레이어 구조 변경                              | `ARCHITECTURE.md`                                      |
| 테스트 구조/컨벤션 변경                          | `TEST.md`                                              |
| 새로운 의존성/도구 추가                          | `CLAUDE.md` (Quick Reference)                          |

### 3단계: 현재 문서 읽기

영향 받는 문서의 현재 내용을 읽어 어떤 섹션이 업데이트 대상인지 파악한다.

## 문서별 업데이트 가이드

### `docs/API.md`

**트리거**: Controller 엔드포인트 추가/수정/삭제, 예외 클래스 변경

업데이트 대상 섹션:

- **엔드포인트 목록** — 테이블에 새 엔드포인트 추가 또는 기존 항목 수정
    - Method, Path, 설명, 상태 코드를 정확히 기재
    - 적절한 카테고리(공개/인증/사용자 API/관리자 API)에 배치
    - 알파벳순 또는 도메인별 논리적 순서 유지

- **예외 계층** — 새 예외 클래스 추가 시 트리 구조에 반영
    - 부모 예외 아래 적절한 위치에 삽입

- **DTO** — 새 DTO 추가 시 관련 설명 추가 (필요한 경우)

- **멱등성** — 멱등성 키가 필요한 새 엔드포인트 추가 시 설명 추가

### `docs/DATABASE.md`

**트리거**: Entity/Repository 추가/수정, init.sql 변경

업데이트 대상 섹션:

- **Entity 목록 테이블** — 새 Entity 행 추가
    - Entity명, 테이블명, Mixin, UNIQUE 제약, 비고 기재
    - 기존 테이블과 동일한 포맷 유지

- **Repository 패턴** — 새로운 패턴이 도입된 경우만 추가

### `docs/ERD.md`

**트리거**: Entity 추가/수정, FK 관계 변경

업데이트 대상 섹션:

- **전체 도메인 관계** — 새 Entity 간 관계 추가
- **도메인별 ERD** — 해당 도메인 섹션에 Mermaid erDiagram 추가/수정
    - 기존 도메인에 속하면 해당 섹션에 추가
    - 새 도메인이면 새 섹션 생성 (번호 부여)
    - 컬럼 타입, PK/FK/UK 표기, 암호화 등 주석 포함

### `docs/PIPELINE.md`

**트리거**: 태스크 추가/수정, 수집/요약 로직 변경

업데이트 대상 섹션:

- **스케줄링 태스크 목록** — 새 태스크 행 추가 (태스크명, 스케줄, 설명)
- **파이프라인 흐름도** — ASCII 다이어그램 수정/추가
- **설계 원칙** — 새로운 원칙이 도입된 경우만 추가

### `docs/ARCHITECTURE.md`

**트리거**: 디렉토리 구조 변경, 새 레이어/모듈 추가

업데이트 대상 섹션:

- **레이어 구조** — 디렉토리 트리에 새 경로 추가
- **시스템 개요** — 시스템 설명 변경 (드물게 발생)

### `docs/CONVENTIONS.md`

**트리거**: 레이어별 패턴 변경, 새로운 컨벤션 도입

업데이트 대상 섹션:

- 해당 레이어의 컨벤션 섹션에 새 패턴 추가/수정
- 새 레이어나 모듈 유형이 추가된 경우 새 섹션 생성

### `docs/INFRASTRUCTURE.md`

**트리거**: Docker 설정, Redis 용도, 환경 설정 변경

업데이트 대상 섹션:

- 해당 인프라 컴포넌트 섹션에 변경사항 반영

### `docs/TEST.md`

**트리거**: 테스트 구조/fixture/컨벤션 변경

업데이트 대상 섹션:

- 테스트 작성 가이드에 변경사항 반영

### `CLAUDE.md`

**트리거**: 주요 기술 스택 변경, 새로운 Gotchas 발견, 커맨드 변경

업데이트 대상 섹션:

- **Quick Reference** — 기술 스택/의존성 변경
- **Commands** — 실행/테스트 커맨드 변경
- **Gotchas** — 새로운 주의사항 추가
- **상세 문서 링크** — 새 문서 추가 시

## 업데이트 원칙

1. **기존 포맷 준수** — 해당 문서의 기존 마크다운 스타일, 테이블 포맷, 들여쓰기를 그대로 따른다
2. **최소 변경** — 변경사항에 직접 관련된 섹션만 수정한다. 기존 내용을 불필요하게 재작성하지 않는다
3. **일관된 순서** — 테이블 행 추가 시 기존 정렬 순서(알파벳, 도메인별, 논리적 순서)를 따른다
4. **Mermaid 문법 검증** — ERD 수정 시 Mermaid 문법이 유효한지 확인한다
5. **코드와 문서의 정합성** — 문서에 기술된 내용이 실제 코드와 정확히 일치하는지 확인한다
6. **한국어 사용** — 기존 문서와 동일하게 한국어로 작성한다

## 실행 절차

```
1. 변경사항 파악       → 검증: 변경된 파일 목록과 내용을 정확히 파악했는가
2. 영향 문서 판별      → 검증: 누락된 문서가 없는가
3. 현재 문서 읽기      → 검증: 수정할 섹션을 정확히 식별했는가
4. 문서 수정          → 검증: 기존 포맷과 일관성을 유지하는가
5. 변경 내용 요약      → 검증: 사용자에게 수정된 문서와 섹션을 명확히 보고했는가
```

## 체크리스트

업데이트 완료 후 다음을 확인한다:

- [ ] 코드 변경사항에 영향 받는 모든 문서가 업데이트되었는가
- [ ] 기존 문서의 포맷(테이블, 코드 블록, 헤딩 레벨)과 일관성이 유지되는가
- [ ] 테이블에 새 행 추가 시 정렬 순서가 맞는가
- [ ] ERD 수정 시 Mermaid 문법이 유효한가
- [ ] 문서 내용이 실제 코드와 정확히 일치하는가
- [ ] 불필요한 섹션을 건드리지 않았는가
- [ ] 한국어로 작성되었는가
